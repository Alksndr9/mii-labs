# Аудит безопасности по OWASP Top 10 (2021): проект «Зелень»

Я ничего не менял, только читал файлы. Проверены `app/src`, `supabase/migrations` + `seed.sql`, оба workflow, `vite.config.ts`, `index.html`, `.gitignore`, `.env.example`, `.mcp.json`.

Главная проблема: **сумму заказа (`total`) присылает клиент, а БД проверяет только `total >= 0`.** Любой авторизованный пользователь может создать заказ на 0 ₽.

## Что сделано хорошо

- **XSS:** нигде нет `dangerouslySetInnerHTML`, `innerHTML` и `eval`. Весь вывод идёт через JSX-экранирование React. `href` формируется только через `<Link to>` с внутренними маршрутами.
- **SQL-инъекции:** везде используется query builder PostgREST (параметризованные запросы). В миграции нет динамического SQL. `fetchMealById(id)` из URL-параметра идёт через `.eq()`, это безопасно.
- **CSRF:** не применим. Авторизация идёт через Bearer JWT в заголовке, а не через cookie.
- **Open redirect:** `from` в `LoginPage` берётся из `location.state`, его можно задать только внутри приложения. Навигация остаётся в пределах роутера.
- **RLS:** включён на обеих таблицах. SELECT заказов ограничен `user_id = auth.uid()`. INSERT разрешён только от своего имени и только со статусом `pending_payment`. UPDATE разрешает только переход `pending_payment → cancelled`, причём это ограничено ещё и правами на колонку (`revoke update` + `grant update(status)`), то есть защита в два слоя. У `anon` нет доступа к заказам. Для `meals` нет политик записи.
- **`user_id default auth.uid()`:** клиент его не передаёт, подделка отсекается `with check`.
- **Ограничения в БД** дублируют клиентскую валидацию: длины полей, формат телефона `^\+7\d{10}$`, enum для статусов и целей, деньги как integer в копейках.
- **`security definer` + `set search_path = ''`** в `health()` закрывает подмену search_path.
- **Секреты:** в коде только `import.meta.env.VITE_*`. `.env` в `.gitignore`, в репозитории только `.env.example` с заглушками. В рабочем дереве нет JWT-подобных строк и service_role. Историю git на наличие `.env` проверить не удалось: команда не прошла по правам доступа. В CI ключи берутся из `secrets`.
- **Недоверие к `localStorage`:** `isCartLine` + рантайм-проверки в `calculateOrderTotal` (`isSafeInteger`, допустимые сроки, корректность промокода) защищают UI от испорченных данных. Сумма для сервера при этом всё равно не защищена, см. F-01.
- **Ошибки:** `toApiError` показывает пользователю общие сообщения, без деталей из БД и стектрейсов. Логи структурированные, в них нет email и пароля, `details` с данными строки не пишутся. В Метрику уходит только имя события ошибки, без контекста.
- **CI/CD:** `permissions: contents: read` на уровне workflow, а `pages: write` и `id-token: write` выданы только джобе deploy. Деплой только из `main` и не из PR. `npm ci` с lockfile, есть шаг `npm audit`. Health-мониторинг с алертом.
- **Аутентификация:** `autoComplete` настроен правильно (`current-password`/`new-password`). `RequireAuth` используется только для UX, а реальную защиту обеспечивает RLS.
- **Аналитика:** `webvisor: false`, то есть сессии с вводом адреса и телефона не записываются.

**Порядок исправления:** F-01 → F-02/F-03 (это одна RPC `create_order`) → F-04 → F-05/F-06 → F-07/F-08, затем остальное.
