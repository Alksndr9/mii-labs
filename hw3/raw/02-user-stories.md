## Personas

**1. Ирина, 29 лет, менеджер по продажам (работает в офисе)**
- **Цель:** обедать и ужинать в пределах ~1500 ккал и не тратить время на готовку.
- **Ограничения:** готова платить не больше, чем сейчас тратит на кафе и доставку. Оформляет заказ со смартфона в обеденный перерыв и тратит на это 5–10 минут. Если цена или условия неясны, бросает оформление.

**2. Дмитрий, 38 лет, IT-специалист (работает из дома, двое детей)**
- **Цель:** снизить вес на 8 кг за 3 месяца и перестать перекусывать.
- **Ограничения:** аллергия на арахис, поэтому аллергены должны быть видны до оплаты. Платит только через СБП. Сначала хочет попробовать 1 день и не настроен на долгую регистрацию.

**3. Марина, 44 года, бухгалтер**
- **Цель:** питаться по рекомендации врача (меньше сахара, дробное питание).
- **Ограничения:** не доверяет новым онлайн-сервисам и читает условия отмены и стоимость доставки. Живёт в новостройке, которую геокодеры находят плохо. Доставка нужна строго до 08:30, до выхода на работу.

**Допущения по бизнес-правилам MVP** (используются в критериях приемки): приём заказов на завтра до 18:00. Слоты доставки: 06:00–08:30 и 19:00–22:00 накануне. Доставку выполняет партнёрская служба, собственной логистики нет. Код из SMS состоит из 4 цифр, действует 5 минут, повторно его можно запросить через 60 секунд.

## Пользовательские истории

### 1. Проверка зоны доставки
**Как** Марина, **я хочу** ввести свой адрес на первом экране и сразу узнать, доставляете ли вы туда, **чтобы** не тратить время на выбор рациона, который мне не привезут.
**Приоритет:** Must have
**Этап:** 1. Первый вход и проверка зоны доставки

```gherkin
Сценарий 1 (позитивный): адрес в зоне доставки
Given пользователь находится на первом экране
When вводит адрес «ул. Ленина, 10» и выбирает его из подсказок
Then отображается сообщение «Доставляем по этому адресу»
And адрес сохраняется для шага оформления
And активна кнопка «Выбрать рацион»

Сценарий 2 (негативный): адрес вне зоны доставки
Given пользователь находится на первом экране
When вводит адрес за пределами полигона зоны доставки
Then отображается сообщение «Пока не доставляем по этому адресу»
And отображается поле «Оставьте телефон — сообщим о запуске»
And кнопка «Выбрать рацион» остаётся доступной с пометкой «Только посмотреть меню»

Сценарий 3 (негативный): адрес не найден геокодером
Given пользователь вводит адрес новостройки
When подсказки не содержат нужного дома
Then отображается ссылка «Нет моего адреса»
And по ссылке открывается ручной ввод (улица, дом, корпус) с проверкой по ближайшему найденному дому
```

### 2. Каталог программ с ценой
**Как** Ирина, **я хочу** видеть все программы на одном экране с ценой за день, калорийностью и числом приёмов пищи, **чтобы** за минуту выбрать подходящую мне по бюджету.
**Приоритет:** Must have
**Этап:** 2. Выбор программы питания

```gherkin
Сценарий 1 (позитивный): просмотр каталога
Given в системе опубликовано 4 программы
When пользователь открывает каталог на экране шириной 360 px
Then каждая карточка показывает название, ккал/день, число приёмов пищи и цену «от N ₽/день»
And все карточки доступны вертикальной прокруткой без горизонтального скролла

Сценарий 2 (негативный): программа недоступна для заказа
Given у программы «2000 ккал» нет свободных мест на ближайшие 7 дней
When пользователь открывает каталог
Then карточка показывается с меткой «Нет мест до ДД.ММ»
And кнопка «Выбрать» на карточке неактивна
```

### 3. Фильтр программ по цели
**Как** Дмитрий, **я хочу** отфильтровать программы по цели «Снижение веса», **чтобы** не сравнивать программы, которые мне не подходят.

```gherkin
Сценарий 2 (негативный): по фильтру ничего нет

```

### 4. Меню программы с составом, КБЖУ и аллергенами
**Как** Дмитрий, **я хочу** посмотреть меню программы по дням с составом, КБЖУ и аллергенами каждого блюда, **чтобы** до оплаты убедиться, что в нём нет арахиса.
**Приоритет:** Must have
**Этап:** 3. Изучение меню набора

```gherkin
Сценарий 1 (позитивный): просмотр блюда
Given пользователь открыл программу «1500 ккал»
When выбирает вкладку «Вт» и нажимает на блюдо «Боул с киноа»
Then открывается карточка блюда с фото, весом в граммах, составом, КБЖУ и списком аллергенов
And над меню указан период «Меню на неделю с ДД.ММ по ДД.ММ»

Сценарий 2 (негативный): у блюда не заполнены аллергены
Given у блюда в админке не заполнено поле «Аллергены»
When контент-менеджер публикует меню
Then система блокирует публикацию с ошибкой «Не указаны аллергены для блюда X»
And неполное блюдо не отображается пользователю

Сценарий 3 (негативный): меню на выбранную неделю ещё не опубликовано
Given меню на следующую неделю не опубликовано
When пользователь переключается на следующую неделю
Then отображается сообщение «Меню появится ДД.ММ»
```

```gherkin
Сценарий 2 (негативный): дедлайн приёма заказа на завтра прошёл
```


### 7. Вход по номеру телефона
**Как** Ирина, **я хочу** войти по номеру телефона и коду из SMS без пароля, **чтобы** оформить заказ за минимальное время.
**Приоритет:** Must have
**Этап:** 5. Регистрация по номеру телефона

```gherkin
Сценарий 1 (позитивный): успешный вход
Given пользователь не авторизован и нажал «Оформить»
When вводит номер +7 9XX XXX-XX-XX и корректный 4-значный код из SMS в течение 5 минут
Then пользователь авторизован
And содержимое заказа (программа, даты, слот) сохранено
And открывается шаг ввода данных доставки

Сценарий 2 (негативный): неверный код
Given пользователь запросил код
When трижды вводит неверный код
Then отображается ошибка «Неверный код»
And ввод блокируется на 5 минут
And отображается таймер до следующей попытки

Сценарий 3 (негативный): SMS не пришло
Given с момента отправки кода прошло меньше 60 секунд
When пользователь пытается запросить код повторно
Then кнопка «Отправить снова» неактивна и показывает обратный отсчёт
And через 60 секунд кнопка становится активной
```

```gherkin
Сценарий 3 (негативный): комментарий превышает лимит
```


### 11. Оплата через СБП или картой

